# R8 / ProGuard（難読化・シュリンク）

- **R8 / ProGuard によるクラス保護**:
    - リリースビルドの難読化・シュリンク（R8）からクラスを保護する必要がある場合（例: Room に JSON
      で永続化されるクラス、WorkManager
      がクラス名で参照する`Worker`など、クラス名がコード外から参照されるもの）は、`app/proguard-rules.pro`
      に個別のクラス名やパッケージ名を書かないでください。
    - 代わりに、保護対象のクラス自身に `androidx.annotation.Keep` を付与してください。リネームやパッケージ移動に追従でき、保護の意図もクラス定義の場所で明示できます。
    - `@Keep` はサブクラスに継承されないため、sealed
      interface/classの各サブクラスなど、保護が必要な型にはそれぞれ個別に付与してください。
    - `app/proguard-rules.pro` には、特定クラスに依存しない汎用的なルール（属性の保持設定など）のみを記述してください。
    - 例外：外部ライブラリがクラスパスにないクラスを参照して R8 が `Missing class` で止まるときは、AGP が出す
      `app/build/outputs/mapping/release/missing_rules.txt` の `-dontwarn` を、ライブラリ名と理由のコメントつきで書いてよい。
      警告を抑えるだけで保持はしないので、自分のクラスの保持には使わないでください。

- **依存ライブラリを追加・更新したら `./gradlew :app:bundleRelease` まで通す**:
    - debug ビルドのテストと Lint は R8 を通らないため、ライブラリ由来の `Missing class` に気づけません（v2.7.0 で
      `review-ktx` を追加したとき、リリースの直前にビルドが失敗した。#262）。

- **`Worker` のクラス名は変更しない**:
    - `@HiltWorker` の `Worker` も、`HiltWorkerFactory` がクラス名（ソース上の完全修飾名）で生成方法を引くため、`@Keep` が必要です。
    - WorkManager は登録済みジョブをクラス名つきで端末の DB に保存しています。`Worker` のクラス名やパッケージを変えると、既存ユーザーの端末に登録済みのジョブが生成できなくなるため変更しないでください。

- **R8 の動作確認は `beta` ビルドタイプで行う**:
    - `beta` は `release` と同じ R8 設定（minify / shrink / ProGuard ルール）を持ち、デバッグ署名・AdMob
      テスト ID で動作します。`./gradlew :app:installBeta` で端末にインストールしてください。
    - 本番の広告ユニットで検証しないでください（無効トラフィック扱いになるリスクがあるため）。
    - `@Keep` の追加や R8 に影響する変更（シリアライズ対象クラス・`Worker` の追加など）を行ったら、`beta`
      ビルドで該当機能が動作することを確認してください。
    - `applicationIdSuffix` は付けていないため、ストア版がインストールされた端末ではアンインストールしてから入れてください。
