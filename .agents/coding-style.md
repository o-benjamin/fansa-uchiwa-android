# コーディングスタイル（メソッド分割・共通化・ファイル構成・変更の範囲）

- **メソッドの行数**:
    - ひとつのメソッドが60行を超える場合には、メソッドの切り出しができないかどうか検討し、可能な場合は再利用可能な単位で切り出してください。
    - そのメソッドに`@Composable`のアノテーションがついている場合、100行を超える場合にコンポーザブルの切り出しを行うようにしてください。
- **メソッドの共通化**:
    - 複数の場所に同じ処理を記述する必要がある際は、メソッドを共通化し、ボイラープレートコードを削減してください。
- **data class**:
    - data classを新規作成する場合、使用するパッケージ配下に新規ファイルを作成し、必ず別ファイルに切り出してください。
- **1ファイル1クラス**:
    - 原則として、class / interface / object / enum class / data class は1ファイルにつき1つだけ定義してください。
    - 新しい型を追加する場合は既存ファイルへ追記せず、対応する名前の別ファイルへ切り出してください。
- **変更の範囲**:
    - タスクと関係ない箇所のリファクタリング（命名の変更・書き直し・整形）は、同じ PR に混ぜないでください。差分が大きくなり、レビューで変更の意図が追えなくなるためです。
    - 範囲外で直したい箇所を見つけたら、`gh issue create` で Issue を立てて記録し、別の PR で対応してください。
    - タスクのために必要な整理（変更する関数の切り出しなど）はタスクの範囲に含まれるので、同じ PR で行ってかまいません。
    - このルールは Kotlin 以外（リソース・Gradle・ProGuard・ドキュメント）の変更にも当てはまります。
