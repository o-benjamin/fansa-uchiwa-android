# Remote Config（アプリを出し直さずに変える値）

Firebase Remote Config の値を読む処理は `data/infra/FirebaseRemoteConfigRemoteSource.kt` に集める（`RemoteConfigDataSource` 経由。#311）。
新しいパラメータを足すときは、この表に1行足し、アプリ側の初期値は「何も出さない・何も変えない」側にする（コンソールに値がなくても、いままでと同じ動きにするため）。例外は `daily_prompts` で、空でも同梱の控えを出す（下の「初期値・止め方がほかのパラメータと逆」）。

| パラメータ | 型 | 使い道 | 初期値 |
|---|---|---|---|
| `daily_prompts` | String（JSON） | 今日のファンサお題（#358）。日付ごとのお題の一覧 | 空文字（同梱の控えから出す。下の「`daily_prompts` の書き方」） |
| `affiliate_materials` | String（JSON） | 保存完了のダイアログに出す、うちわの材料の Amazon アソシエイトのリンク | 空文字（リンクの欄を出さない） |
| `ai_material_enabled` | Boolean | AI 素材（#315）の入口を出すか。サーバー（`functions/src/entrySwitch.ts`）も同じ値を見て、閉じていれば生成を断る | `false`（入口を出さない） |
| `min_version_code` | Number | 更新の案内（#428）。今の版の versionCode がこれより小さければ、起動するたびに閉じられる更新のダイアログを出す | `0`（出さない） |
| `force_version_code` | Number | 更新の案内（#428）。今の版の versionCode がこれより小さければ、閉じられない更新のダイアログを出す。**致命的な不具合のときだけ** | `0`（出さない） |

取得は、ホームが前に出たとき（`daily_prompts` と `ai_material_enabled`）と、うちわのプレビュー画面を開いたとき（`affiliate_materials`）、起動して最初にホームを開いたとき（`min_version_code`・`force_version_code`）。`ai_material_enabled` の入口は、お題のカードの副ボタン「AIで素材を作る」に出す（#340。お題のカードを閉じた日は入口も出ない）。どこで取得しても、すべてのパラメータが新しい値になる。最小取得間隔は1時間なので、**コンソールで公開してから端末に届くまで最大約1時間**かかる。取得に失敗したら前回の値を使う（なければ空）。

## `min_version_code`・`force_version_code`（更新の案内）

アプリは起動して最初にホームを開いたときに1回だけ、この2つと Play の In-App Updates の答えから案内を決める（`update/UpdatePromptPolicy.kt`）。編集画面には出さない。

- `force_version_code` より古い：閉じられない更新のダイアログ。ただし Play が「新しい版がある」と答えたときだけで、Play に聞けない端末やまだ新しい版が届いていない端末では、閉じられるダイアログに下げる（更新できないまま使えなくしないため）
- `min_version_code` より古い：閉じられる更新のダイアログ（「あとで」）。起動するたびに出る
- どちらにも当たらず、Play に新しい版があって3日以上入っていない：Play の柔軟な更新の画面（`UpdatePromptPolicy.FLEXIBLE_MIN_STALENESS_DAYS`）
- ダイアログの「更新する」は Play の即時更新の画面を出し、出せなければ Play ストアのページを開く。案内を出した起動では、最初のインタースティシャルを出さない
- 届くまで最大約1時間（最小取得間隔）。そのあとの次の起動から効く

### 上げるとき（運用の決まり。#428）

`min_version_code` は、新しい版を出してすぐには上げない。次のすべてに当たるときだけ上げる。

1. 上げる先の版が 100% で配信されてから **14日以上**たっている
2. その版で、Crashlytics にその版から出た新しい FATAL がない
3. 上げる先は「ひとつ前の安定した版」の versionCode。出したばかりの版は指定しない
4. Remote Config の変更なので、上げるたびにオーナーの承認をもらう

`force_version_code` は、その版のままだとデータが消える・起動できないなどの致命的な不具合があり、直した版が配信済みのときだけ使う。直した版の versionCode を入れ、オーナーの承認をもらってから公開する。不具合が片づいたら `0` に戻す。

### 確かめる・うまく出ないとき

- **確かめる**：Play からの答えは Play ストアから入れたアプリでしか返らないので、クローズドテスト版（または内部テスト版）で試す。条件 `app.build`（versionCode）で自分の版だけに大きい値を配ると、その版でダイアログが出る。DebugView に `show_update_prompt`（`source=min`・`force`・`flexible`）と、「更新する」で `tap_update` が出る
- **出ない**：公開から1時間以内なら、まだ届いていない。起動して最初のホームでしか決めないので、アプリを完全に終了してから開き直す。ログのタグ `AppUpdate`（Play への問い合わせの失敗）と `RemoteConfig` を見る

## `affiliate_materials` の書き方

```json
{
  "items": [
    { "id": "jumbo_uchiwa", "label": "ジャンボうちわ", "url": "https://www.amazon.co.jp/dp/XXXXXXXXXX?tag=xxxx-22" },
    { "id": "mirror_sheet", "label": "ミラーシート", "url": "https://amzn.to/xxxxxxx" }
  ]
}
```

- `id`：計測に使う英小文字の名前。GA4 の `tap_preview_affiliate` の `affiliate_item` に出る（レポートで見るには、GA4 でカスタムディメンション `affiliate_item` の登録が要る）
- `label`：画面に出す材料の名前（ボタンは「〇〇をAmazonで見る」になる）
- `url`：開く先。**`https` で、ホストが `amazon.co.jp` / `www.amazon.co.jp` / `amzn.to` / `amzn.asia` のものだけ**。設定の誤りで任意の URL を開かないための制限（`AffiliateLinksParser`）
- 出すのは先頭から**3件まで**。`id` が重複した項目は先の1件だけ残る。`id`・`label`・許可した `url` のどれかが欠けた項目は捨てられる
- 商品の画像と価格は出さない（Amazon が提供する仕組みを通さないと使えない。アソシエイトの規約）
- 「PR」の表示と「Amazonのアソシエイトとして、…」の文は、リンクと必ず一緒に出す（ステマ規制とアソシエイトの規約）。文は `strings.xml` にあり、Remote Config では変えられない

**初めて公開する前に**、プライバシーポリシーの外部サービス一覧とデータセーフティの申告に、Remote Config と Amazon アソシエイトが載っていることを確かめる（経緯は #313）。

## `ai_material_enabled` の使い方

- アプリは値が `true` のときだけ入口を出す。だれに出すかは、Remote Config の条件（版・国・ユーザーの割合など）で分ける
- サーバーは端末の条件を評価できないので、初期値と条件の値の**どれか1つでも `true` なら開いている**とみなす。すぐ止めたいときは、すべて `false` にして公開する（サーバーは1分以内に断り始める。アプリの入口が消えるのは、公開から最大約1時間たったあとにホームが前に出たとき。それまでに残った入口から開いても、サーバーが断る）
- 開ける前にそろえるもの（プライバシーポリシー・報告の TTL・断る名前の一覧など）は `functions/README.md` の「入口を初めて開ける前に」

## `affiliate_materials` を止める・確かめる・うまく出ないとき

- **止める**：値を空文字にして公開する（アプリの出し直しは要らない。反映まで最大約1時間）
- **確かめる**：beta ビルドを入れてうちわを保存する。DebugView に `view_preview_affiliate`（保存完了のダイアログにリンクを出したとき）と `tap_preview_affiliate` が出る
- **リンクが出ない**
    - 値が `{"items": [...]}` の形でない、または項目が1件もあるのに1件も使えない → Crashlytics の非致命の例外に `affiliate_materials` で始まるメッセージが出る（1プロセスに1回）
    - 取得そのものの失敗（オフライン・回数制限・プロジェクトの設定の誤り）は想定内として握る。ログのタグ `RemoteConfig` で見る
    - 公開から1時間以内なら、まだ届いていない可能性がある
- 持ち主が変わるときは、Firebase プロジェクトを移せば Remote Config の値もそのまま渡る。Amazon アソシエイトのアカウントは移せないので、新しい持ち主が自分のアカウントの `tag=` 付きリンクに差し替える

## `daily_prompts` の書き方

```json
{
  "notify": true,
  "prompts": [
    { "date": "2026-11-16", "id": "20261116", "text": "ピースして" },
    { "date": "2026-11-17", "id": "20261117", "text": "指ハートして" }
  ]
}
```

- `date`：お題を出す日（`YYYY-MM-DD`）。端末の日付と同じ1件を出すので、同じ日なら全員が同じお題を見る。同じ日付が2件あれば先の1件
- `id`：計測の `prompt_id` に出る名前（`view_daily_prompt` など。#360）。日付の `YYYYMMDD` にそろえる。`default_` で始めない（同梱の控えと見分けるため）
- `text`：お題の文言。**16文字まで**、URL（`://`・`www.`）を入れない。実在の人名・グループ名・曲名・歌詞、下品・過激な文言を入れない。文字数はコードポイントで数えるので、組み合わせの絵文字（肌の色つき・家族・旗など）は1つで2文字以上になる。11文字以上は、うちわに置く文字が `10 / 文字数` の大きさに縮む（`EditDecorationRepository` の `DAILY_PROMPT_CHARS_AT_FULL_SCALE`、#360）。同梱の控えはどれも10文字以下なので、11文字以上を初めて配る前に beta ビルドの編集画面で見た目を確かめ、はみ出す・小さすぎるならこの値を直す
- `notify`：通知（#361）で使う予定。今のアプリは読まない
- 過去の日付の項目は消してよい（アプリは今日の分しか見ない）。同梱の控えの1件をその日だけ差し替えたいときは、その日付の項目を足す
- 端末に残っている値（前回取得した値）でまずお題を出し、取得できたら新しい値で出し直す

### うまく出ないとき

- 値が `{"prompts": [...]}` の形でない、項目があるのに1件も使えない、または JSON が壊れているとき → Crashlytics の非致命の例外に `daily_prompts` で始まるメッセージが出て（1プロセスに1回）、同梱の控えを出す
- 一部の項目だけが決まりに合わない（`date`・`id` が欠けた、`date` の形が違う、文言が空・17文字以上・URL 入り、同じ日付の2件目）とき → その項目だけ捨てられ、その日は控えが出る。Crashlytics には出ない。ログのタグ `DailyPrompt` に「`prompts` の n 件目を捨てた」と出る
- 取得そのものの失敗は、ログのタグ `RemoteConfig` で見る。公開から1時間以内なら、まだ届いていない可能性がある

### 初期値・止め方がほかのパラメータと逆

- **値が空（未設定）、または取得できないときは、アプリに同梱の控え（`DailyPromptDefaults`、30件）から日付の順に出す**。今日の日付の分が一覧にないときも控えを出す。取得できない端末・設定を誤ったときでも、カードを空にしないため
- **お題を止めるときは、空文字ではなく `{"prompts": []}` を公開する**（空文字だと控えが出る）。反映まで最大約1時間。止める JSON を書き間違えても止まらず控えが出る（配っていた文言は消える）ので、公開したあと beta ビルドでホームにお題が出ないことを確かめる
- 控えの文言を変えるときはアプリの出し直しになる。`id` は計測に出るので、同じ動作の言い換えなら変えない

## 特定のインストールだけに機能を出す（`app.firebaseInstallationId`）

全員に出す前に、テストする人の端末だけで機能を開けたいとき（最初の使い道は `ai_material_enabled` のクローズドテスト。#411）。クローズドテストのテスターは全員が同じ版を受け取るので、版の番号（`app.build`）の条件では絞れない。

1. テストする人に、設定画面のいちばん下の「インストール ID」をタップしてコピーしてもらう（AI 素材を使ったあとは、その下に「利用者 ID」も出る。問い合わせ用の別の ID で、この条件には使えない）
2. Firebase コンソールの Remote Config で条件を作る：`app.firebaseInstallationId in ['<コピーした ID>']`（複数なら並べる）
3. パラメータの初期値は `false` のまま、その条件の値だけ `true` にして公開する（届くまで最大約1時間）

- インストール ID は端末ではなくアプリのインストールごとに振られ、アンインストール・アプリのデータ消去で変わる。変わったら 1 からやり直し、古い ID は条件から消す
- 全員に開けるときは、初期値を `true` にしてこの条件を消す（残すと、あとで初期値を戻したときにその端末だけ開いたままになる）
- 持ち主が変わるときは、前の持ち主やテスターの ID の条件を消す
- `ai_material_enabled` の場合、サーバー（`functions/`）は端末の条件を評価できず、条件の値が1つでも `true` なら開いているとみなす。条件を置く前に、`functions/README.md` の「入口を初めて開ける前に」のうち `blockedNames`・予算アラート・ログベースのアラートをそろえる（費用と名前の一覧は、開くのが1台でも効くため）。プライバシーポリシーとデータセーフティ、報告ボタン（#339）は、送る内容を知っているテストする人のインストールだけに開けるあいだは後でよく、全員に開ける前にそろえる。そのため条件にはテストする人のインストールだけを入れ、ほかの利用者に開かない
