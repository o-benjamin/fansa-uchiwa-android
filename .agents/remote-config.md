# Remote Config（アプリを出し直さずに変える値）

Firebase Remote Config の値を読む処理は `data/infra/FirebaseRemoteConfigRemoteSource.kt` に集める（`RemoteConfigDataSource` 経由。#311）。
新しいパラメータを足すときは、この表に1行足し、アプリ側の初期値は「何も出さない・何も変えない」側にする（コンソールに値がなくても、いままでと同じ動きにするため）。例外は `daily_prompts` で、空でも同梱の控えを出す（下の「初期値・止め方がほかのパラメータと逆」）。

| パラメータ | 型 | 使い道 | 初期値 |
|---|---|---|---|
| `daily_prompts` | String（JSON） | 今日のファンサお題（#358）。日付ごとのお題の一覧 | 空文字（同梱の控えから出す。下の「`daily_prompts` の書き方」） |
| `affiliate_materials` | String（JSON） | 保存完了のダイアログに出す、うちわの材料の Amazon アソシエイトのリンク | 空文字（リンクの欄を出さない） |

取得は、ホームが前に出たとき（`daily_prompts`）と、うちわのプレビュー画面を開いたとき（`affiliate_materials`）。どちらで取得しても、すべてのパラメータが新しい値になる。最小取得間隔は1時間なので、**コンソールで公開してから端末に届くまで最大約1時間**かかる。取得に失敗したら前回の値を使う（なければ空）。

## `affiliate_materials` の書き方

```json
{
  "items": [
    { "id": "jumbo_uchiwa", "label": "ジャンボうちわ", "url": "https://www.amazon.co.jp/dp/XXXXXXXXXX?tag=xxxx-22" },
    { "id": "mirror_sheet", "label": "ミラーシート", "url": "https://amzn.to/xxxxxxx" }
  ]
}
```

- `id`：計測に使う英小文字の名前。GA4 の `tap_preview_affiliate` の `affiliate_item` に出る（レポートで見るには、GA4 でカスタムディメンション `affiliate_item` の登録が要る）
- `label`：画面に出す材料の名前（ボタンは「〇〇をAmazonで見る」になる）
- `url`：開く先。**`https` で、ホストが `amazon.co.jp` / `www.amazon.co.jp` / `amzn.to` / `amzn.asia` のものだけ**。設定の誤りで任意の URL を開かないための制限（`AffiliateLinksParser`）
- 出すのは先頭から**3件まで**。`id` が重複した項目は先の1件だけ残る。`id`・`label`・許可した `url` のどれかが欠けた項目は捨てられる
- 商品の画像と価格は出さない（Amazon が提供する仕組みを通さないと使えない。アソシエイトの規約）
- 「PR」の表示と「Amazonのアソシエイトとして、…」の文は、リンクと必ず一緒に出す（ステマ規制とアソシエイトの規約）。文は `strings.xml` にあり、Remote Config では変えられない

**初めて公開する前に**、プライバシーポリシーの外部サービス一覧とデータセーフティの申告に、Remote Config と Amazon アソシエイトが載っていることを確かめる（経緯は #313）。

## `affiliate_materials` を止める・確かめる・うまく出ないとき

- **止める**：値を空文字にして公開する（アプリの出し直しは要らない。反映まで最大約1時間）
- **確かめる**：beta ビルドを入れてうちわを保存する。DebugView に `view_preview_affiliate`（保存完了のダイアログにリンクを出したとき）と `tap_preview_affiliate` が出る
- **リンクが出ない**
    - 値が `{"items": [...]}` の形でない、または項目が1件もあるのに1件も使えない → Crashlytics の非致命の例外に `affiliate_materials` で始まるメッセージが出る（1プロセスに1回）
    - 取得そのものの失敗（オフライン・回数制限・プロジェクトの設定の誤り）は想定内として握る。ログのタグ `RemoteConfig` で見る
    - 公開から1時間以内なら、まだ届いていない可能性がある
- 持ち主が変わるときは、Firebase プロジェクトを移せば Remote Config の値もそのまま渡る。Amazon アソシエイトのアカウントは移せないので、新しい持ち主が自分のアカウントの `tag=` 付きリンクに差し替える

## `daily_prompts` の書き方

```json
{
  "notify": true,
  "prompts": [
    { "date": "2026-11-16", "id": "20261116", "text": "ピースして" },
    { "date": "2026-11-17", "id": "20261117", "text": "指ハートして" }
  ]
}
```

- `date`：お題を出す日（`YYYY-MM-DD`）。端末の日付と同じ1件を出すので、同じ日なら全員が同じお題を見る。同じ日付が2件あれば先の1件
- `id`：計測の `prompt_id` に出る名前（`view_daily_prompt` など。#360）。日付の `YYYYMMDD` にそろえる。`default_` で始めない（同梱の控えと見分けるため）
- `text`：お題の文言。**16文字まで**、URL（`://`・`www.`）を入れない。実在の人名・グループ名・曲名・歌詞、下品・過激な文言を入れない。文字数はコードポイントで数えるので、組み合わせの絵文字（肌の色つき・家族・旗など）は1つで2文字以上になる。11文字以上は、うちわに置く文字が `10 / 文字数` の大きさに縮む（`EditDecorationRepository` の `DAILY_PROMPT_CHARS_AT_FULL_SCALE`、#360）。同梱の控えはどれも10文字以下なので、11文字以上を初めて配る前に beta ビルドの編集画面で見た目を確かめ、はみ出す・小さすぎるならこの値を直す
- `notify`：通知（#361）で使う予定。今のアプリは読まない
- 過去の日付の項目は消してよい（アプリは今日の分しか見ない）。同梱の控えの1件をその日だけ差し替えたいときは、その日付の項目を足す
- 端末に残っている値（前回取得した値）でまずお題を出し、取得できたら新しい値で出し直す

### うまく出ないとき

- 値が `{"prompts": [...]}` の形でない、項目があるのに1件も使えない、または JSON が壊れているとき → Crashlytics の非致命の例外に `daily_prompts` で始まるメッセージが出て（1プロセスに1回）、同梱の控えを出す
- 一部の項目だけが決まりに合わない（`date`・`id` が欠けた、`date` の形が違う、文言が空・17文字以上・URL 入り、同じ日付の2件目）とき → その項目だけ捨てられ、その日は控えが出る。Crashlytics には出ない。ログのタグ `DailyPrompt` に「`prompts` の n 件目を捨てた」と出る
- 取得そのものの失敗は、ログのタグ `RemoteConfig` で見る。公開から1時間以内なら、まだ届いていない可能性がある

### 初期値・止め方がほかのパラメータと逆

- **値が空（未設定）、または取得できないときは、アプリに同梱の控え（`DailyPromptDefaults`、30件）から日付の順に出す**。今日の日付の分が一覧にないときも控えを出す。取得できない端末・設定を誤ったときでも、カードを空にしないため
- **お題を止めるときは、空文字ではなく `{"prompts": []}` を公開する**（空文字だと控えが出る）。反映まで最大約1時間。止める JSON を書き間違えても止まらず控えが出る（配っていた文言は消える）ので、公開したあと beta ビルドでホームにお題が出ないことを確かめる
- 控えの文言を変えるときはアプリの出し直しになる。`id` は計測に出るので、同じ動作の言い換えなら変えない
